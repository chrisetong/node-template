# 安全操作

## 密钥管理

- `.env.production` 权限设为 `600`，不得提交版本库或打进镜像。
- JWT、数据库、Redis、管理员密码必须独立且随机。
- CI/CD 使用受控 Secret Store 注入，不在构建日志中输出变量。
- 生产保持 `SWAGGER_ENABLED=false`；临时启用后立即关闭。

## JWT 密钥轮换

1. 确认维护窗口并通知用户会重新登录。
2. 生成新的 32 字符以上随机密钥。
3. 更新 Secret Store 或 `.env.production` 中的 `JWT_SECRET`。
4. 重建或重启 Server。
5. 验证旧 Token 失效、新登录正常。
6. 删除旧密钥的临时副本。

当前模板不支持双密钥平滑验证，轮换会使所有旧 JWT 立即失效，这是预期的安全行为。

## 数据库和 Redis 密码轮换

数据库密码先在 MySQL 创建或修改应用账号凭据，再更新 `DATABASE_URL`、`MYSQL_PASSWORD` 并重启 Server。验证成功后再撤销旧凭据。

Redis 密码轮换需要同时更新 Redis 服务和 Server 配置。安排维护窗口，更新 `REDIS_PASSWORD` 后重启 Redis 与 Server；现有登录会话可能失效。

## 代理和客户端 IP

`TRUST_PROXY_HOPS` 必须等于从应用向外数的可信代理层数：

- 浏览器直接经过 Web Nginx：1；
- 外部 HTTPS 代理再经过 Web Nginx：2。

不要为了“获取真实 IP”设置任意信任。代理链变化时，应使用测试请求核对审计日志中的 IP。

## 管理员安全

- 超级管理员只用于权限和系统初始化，不作为日常业务账号。
- 每个管理员使用独立账号，不共享密码。
- 管理员离职或设备丢失时，立即禁用账号并检查审计日志。
- 角色、菜单、数据范围和管理员状态变更应纳入告警。
- Seed 不会重置已有管理员密码；密码恢复必须走受控运维流程。

## 安全事件处理

1. 保存日志、审计记录、时间范围、来源 IP 和相关账号。
2. 禁用受影响账号或撤销角色，使旧会话立即失效。
3. 必要时轮换 JWT、数据库、Redis 和外部服务密钥。
4. 检查用户、角色、菜单、部门范围和上传文件是否被修改。
5. 从可信备份恢复前先保留故障数据库副本。
6. 修复后增加回归测试并记录事件原因与时间线。

不要在排障群、工单或截图中粘贴 Token、密码、完整 `.env` 或数据库备份。
